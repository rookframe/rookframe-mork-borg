# RFG-331 review fixes

Base: `323215f9d7b6bbd9b00c6d2896377212a89d0fc1`. These changes resolve the two documented Standards violations and all three verified Spec findings reviewed against Package 1.0.122. The version and published Manifest are unchanged here; the coordinating task owns the superseding release and whole-workspace verification.

## Resolution

- Translate the native attack choices and guidance through the Package catalog. Project raw ability/range data and translate complete HUD attack/companion templates before formatting. Preserve authored/custom names, Actor data, IDs, dice requests and Action Logs. Stateless Attack/Companion HUD adapters now use RefCounted; their authored managed action Controls and lifecycle-bearing action Nodes remain ordinary Godot scenes.
- Route `companion.cancel` through the Authority's recorded melee/defence route before the first client reply arrives. Existing authority Participant/session checks still decide whether cancellation is permitted. Closing either authored task during an accepted-but-undelivered start cancels the underlying requested Throw; a routed defence also disappears from its inbox, and later completions apply no effects.
- Resolve source Rooks from the initiating Actor and SDK `scenes.current()`, including sole-Actor HUD fallback. Ignore unrelated selected Rooks and inactive Scenes. With multiple matching Rooks and no matching preferred Rook, the authored Power/Item panel offers the existing stock OptionButton source choice. Once an action starts, it retains its captured Actor/source; ordinary selection changes do not cancel it or replace the source.
- Remove literal `main` Scene assumptions from attack presentation and targeted Authority validation. Existing Authority `context.distance()` validates current-Scene spatial context; no client Scene ID is trusted. Melee/Defence/Power additionally retain their chosen Rook pair(s) and check that existing distance operation succeeds before advancing a pending spatial action. Special actions already perform this check. This is active-Scene lifetime validation, not a new range revalidation policy. The extra check is necessary because valid launch-time Rooks can become inactive before a human Throw completes. Untargeted actions have no captured recipient pair, and sheet Power casting retains Window Dice and its existing behavior.
- Match the generated `creature:<attack id>` identity for a fresh Creature profile, before Inventory has been materialized. Edited Inventory copies continue to require their exact inventory identity, including two copies of one source attack. This was reproduced while checking the required targeted companion handoff.

The possible duplicated-controller smell was assessed and intentionally suppressed. Each authored Power, Item and Recovery controller owns distinct domain submission/validation and explicit Godot signal/lifecycle composition. Extracting their Button properties, signals and Window close plumbing into a generic controller would wrap ordinary Godot UI and add indirection without introducing a deeper domain capability. The existing independently authored controllers and their verified close/reopen behavior are retained, consistent with the user SDK design rule.
